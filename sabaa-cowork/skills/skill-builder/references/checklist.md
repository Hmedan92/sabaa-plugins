# قبل ما يحفظ: ٩ أسئلة، و٣ دقايق

بتنطبق على أي Skill: كتبته إنت، أو زميل، أو نزل من الإنترنت.

## فهرس

١. الأسئلة التسعة
٢. وصف ضعيف ووصف منيح
٣. هيكل الفولدر
٤. الطلب الكامل لكتابة Skill
٥. أخطاء شائعة

## ١. الأسئلة التسعة

| # | السؤال | الجواب الصح |
|---|---|---|
| ١ | **الاسم** | صغير وشَرطات، بدون claude أو anthropic، ونفس اسم الفولدر. |
| ٢ | **الحقول** | name وdescription، والمسموح بس: license، compatibility، metadata، allowed-tools. |
| ٣ | **الوصف** | صيغة الغائب؟ فيه «متى»؟ أقل من ١٠٢٤ حرف؟ |
| ٤ | **الجسم** | أقل من ٥٠٠ سطر، وما فيه شروحات Claude بيعرفها؟ |
| ٥ | **المراجع** | على مستوى واحد، وكل خطوة بتسمّي ملفها؟ |
| ٦ | **السكربتات** | بـ ${CLAUDE_SKILL_DIR}، وما في مسار جهاز حدا (/Users/…)؟ |
| ٧ | **الأسرار** | ما في مفتاح ولا كلمة سر ولا رابط فيه key= بأي ملف؟ |
| ٨ | **الفحص** | قائمة تحقّق بتنفحص فعلاً، وحلقة لحتى يطلع الفحص نضيف؟ |
| ٩ | **المخرج** | خيار واحد افتراضي، مش قائمة؟ |

ولـSkill منزّل من برّا، سؤال عاشر: في شي جوّاته بيطلب يعمل شي ما إله علاقة بالشغلة؟

**شكل الرد:** كل مشكلة بسطر مع سببها، ووقّف. التصليح بعد موافقة المستخدم.

## ٢. وصف ضعيف ووصف منيح

| ضعيف | ليش | منيح |
|---|---|---|
| «أنا أكتب محاضر اجتماعات احترافية ومرتّبة بأفضل شكل ممكن.» | صيغة المتكلّم، وما فيه متى. | «تكتب محضر اجتماع بقالب الشركة من ملاحظات أو نص مفرّغ: الحضور، والقرارات، وجدول مهام بالمسؤول والموعد… استخدمها عندما يرفع المستخدم ملاحظات اجتماع أو تفريغ تسجيل ويطلب محضراً أو قائمة مهام. | «محاضر، اجتماعات، قرارات، مهام، Word.» | كلمات بدون جملة. | — |

## ٣. هيكل الفولدر

```
name/                 ← اسم الفولدر = name
├── SKILL.md          ← الوحيد الإجباري
├── references/       ← اختياري: قوالب، جداول، قواعد طويلة
├── scripts/          ← اختياري: حساب وفحص
└── assets/           ← اختياري: ملفات بتنسخ أو بتتعبّى (قالب Word، شعار)
```

**الـfrontmatter اللي بيرفض الرفع:**
```
---
name: apa-citations
description: ترتّب قائمة المراجع…
version: 2.0
dependencies: python>=3.9
---
```
**اللي بينرفع:**
```
---
name: apa-citations
description: ترتّب قائمة المراجع…
compatibility: Python 3
---
```

**قائمة تحقّق منيحة (بتنفحص):**
- «كل مهمة إلها مسؤول وموعد، أو مكتوب "غير محدّد".»
- «مجموع الساعات بالتقرير = مجموع السجل، بالدقيقة.»
- «شغّل check_refs.py على القائمة والمسودة، لحتى يطبع OK.»

**وضعيفة:** «تأكّد إنه كل شي صح.» «راجع الأرقام.» «خلّي المراجع مرتّبة.»

## ٤. الطلب الكامل لكتابة Skill (اللي بيعلّمه الكورس)

> اكتبلي Skill اسمه [الاسم]. بيحوّل [المدخل] لـ[المخرج] [بالشكل الثابت]: [الأقسام]. إذا [الحالة الطرفية]، يكتب [شو] وما يخترع. حط [القالب أو القواعد] بملف references/[اسم].md، وخلّي الخطوة اللي بتحتاجه تسمّيه. [إذا في حساب: اكتب سكربت بـ scripts/[اسم].py وشغّله بمسار ${CLAUDE_SKILL_DIR}، وخلّي الخطوة الأخيرة حلقة: افحص، صلّح، أعد لحتى يطبع OK.] بالآخر قائمة تحقّق بتنفحص. التزم بالقواعد الرسمية: الوصف بصيغة الغائب، شو بيعمل ومتى ينستعمل، أقل من ١٠٢٤ حرف، والجسم أقل من ٥٠٠ سطر، وبالـfrontmatter بس الحقول المسموحة. ورجيني الفولدر قبل ما تحفظ.

لـSkill من شغل حقيقي، زيد: شو اللي Claude ما بيعرفه عن القالب (الأقسام، والترتيب، والحالات اللي بتصير)، ومثال حقيقي مرفوع («هاد شكل النتيجة اللي بدّي ياها»).

## ٥. أخطاء شائعة

- وصف عام أو بصيغة المتكلّم ← صيغة الغائب و«استخدمها عندما…» بكلمات المستخدم.
- كل التفاصيل بالوصف ← الوصف بيتحمّل بكل محادثة. التفاصيل للجسم أو references.
- حقول منسوخة من أمثلة قديمة (version، author) ← الرفع بيفشل بدون سبب واضح.
- اسم الفولدر غير اسم الـSkill ← وخاصة لما حدا ينسخ فولدر ويغيّر الاسم بالملف بس.
- مرجع جوّا مرجع ← كل مرجع بيأشّر عليه SKILL.md مباشرة.
- مسار سكربت من الجهاز ← "${CLAUDE_SKILL_DIR}/scripts/…".
- مفتاح بالـSkill ← الـSkill بينشارك وبينرفع. اعتبره انكشف وغيّره.
- «تأكّد إنه صح» بدل فحص ← اكتب شو بالضبط لازم يتطابق مع شو.
- Skill واحد لكل شي ← بيكبر ووصفه بيصير عام.
- zip فيه الملفات بدون الفولدر ← الرفع ما بيلاقي الـSkill.
